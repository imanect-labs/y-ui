# calc（段階 2: 画面内で完結する計算）仕様草案

状態: 実装済み（0.7.0）。評価: [eval-results-2026-10-15-calc.md](eval-results-2026-10-15-calc.md)（Shiki の説明で 95.8%）。§7 は未決。

## 1. 目的と範囲

ローン返済・料金の試算・割り勘のように、利用者が値を動かすと結果が変わる図を、モデルにデータとして書かせる。

- 入力（スライダー・数の増減・選択）と、それから計算する式と、結果の表示だけを持つ。
- **画面の中で完結する。** サーバーを呼ばない・保存しない・他の図や本文を読まない。同じソースは誰が開いても同じ初期表示になる。
- 段階 1 と同じく、表示されるのは文字と数値だけ。式は Yui が自分で解釈し、JavaScript として実行しない。

範囲外: 外部データの取得、入力の保存・共有、条件で表示を切り替える UI、文字列の加工（連結以外）。これらは段階 3（ホストのアクション）で扱う。

## 2. 記法

````
```ui
calc 住宅ローンの試算
借入額 = slider 500..10000 step 100 初期 3000 万円
金利 = slider 0.1..5 step 0.05 初期 1.5 %
期間 = slider 5..35 初期 35 年
月利 = 金利 / 100 / 12
回数 = 期間 * 12
毎月の返済額 = 借入額 * 10000 * 月利 / (1 - (1 + 月利) ^ -回数) 円
総返済額 = 毎月の返済額 * 回数 / 10000 万円
show 毎月の返済額 | 総返済額
note: 元利均等返済の概算です。
```
````

1 行が 1 つの名前の定義。`名前 = 中身 [単位]`。

| 中身 | 意味 |
|---|---|
| `slider 最小..最大 [step 刻み] [初期 値]` | スライダー。初期が無ければ最小 |
| `count 最小..最大 [初期 値]` | 数の増減（－ / ＋）。整数 |
| `choice 表示名=値 \| 表示名=値 …` | 選択（切り替えボタン）。最初が初期。値は数値 |
| `toggle [初期 オン]` | オン / オフ（1 / 0） |
| 式 | 計算（§3）。前に定義した名前だけを参照できる |

- 名前は日本語でよい（`毎月の返済額`）。空白・記号（`+-*/^()=,|`）を含まない。
- 単位は表示用の文字列。計算には使わない（`万円` と書いても値は変わらない）。
- `show A | B`: 大きく出す結果。無ければ最後の式を出す。他の式は「計算の内訳」として小さく出す。
- `hide: 月利, 回数`: 途中の計算を内訳に出さない。
- `round: 0`（既定）: 結果の表示の小数桁。名前ごとに `毎月の返済額 = … 円 round 0` とも書ける。

## 3. 式

- 数値・名前・`+ - * / ^`・括弧・単項の `-`。
- 関数: `min(a, b, …)` `max(…)` `round(x[, 桁])` `floor` `ceil` `abs` `sqrt` `if(条件, 真, 偽)`。
- 比較: `< <= > >= == !=`（1 / 0 を返す）。`and` `or` `not`。
- 数値は §6 と同じ書き方を受ける（`1,000` `3万` は不可。式の中は半角の数字と小数点だけ。誤読を避けるため）。
- 0 で割る・定義域外（負の数の `sqrt`、非常に大きな `^`）は結果を「—」と表示し、診断を出す。NaN・Infinity を画面に出さない。
- 評価は前から順に 1 度だけ。循環は書けない（前の名前しか参照できない）。式の長さは 200 文字、名前は 30 個まで。

## 4. 表示

- 入力を上に並べ（ラベル・現在の値と単位・操作部品）、結果を下に大きく出す。結果の下に内訳（名前 = 値 単位）。
- 「式を見る」で、各結果の式を名前のまま表示する（モデルの式の誤りを利用者が見抜けるように）。
- キーボード: スライダーは矢印キーで刻みずつ、Page Up / Down で 10 刻み。count は ± ボタンと矢印。choice はラジオボタンの集まり。値の変化は読み上げ領域に結果だけを出す。
- 書き出し（PNG / SVG / コピー）は、その時点の入力値で描いた静止画と、入力値・結果の表。テキスト化（toText）は、初期値での結果と式の一覧。
- ストリーミング中は、入力の行が揃った分だけ部品を出し、式は確定した行から計算する（未定義の名前を参照する式は「—」）。

## 5. 安全性

- 式の構文木を Yui が作って評価する。`eval`・`Function`・プロパティアクセス・文字列の生成は使わない。名前の解決は calc の中の表だけ。
- 計算量の上限: 1 回の評価で演算 10,000 回まで（関数は再帰しないので、名前 30 × 式 200 文字で十分に収まる）。
- 入力の範囲はソースで固定。値は範囲に丸める（URL やホストから値を注入する経路は持たない）。
- 状態（入力の現在値）は図の中だけ。保存しない。共同編集のノートでも、各閲覧者の手元だけで動く。

## 6. 誤りへの備え

モデルが式を誤ると、もっともらしい誤った数字が出る。段階 1 の図より影響が大きいので、次を必須にする。

- 「式を見る」（§4）と、テキスト化での式の一覧。
- `note:` が無い calc には「概算」の注記を自動で付ける（ホストが切れる）。
- 評価: 課題ごとに、初期値と 2 つの別の入力値での正しい結果を持ち、相対誤差 0.5% 以内を合格とする。ローン・料金・割り勘・税込み・単位換算・損益分岐など 30 課題。採用の基準は Luna で 90% 以上、式の誤りによる誤答 5% 以下。
