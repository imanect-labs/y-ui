## 読み取れること

1. **グラフ・数値カードは、Yui（完全版）が今の emit_ui より正確で、軽く、速い。** A が表現できる種類で C は 99.0%（A 91.4%）。図を出すべき課題だけなら C・D は 100%、A は 89.4%。トークンは A の約 3 分の 1、応答時間は約半分（A は修正の往復が平均 1.58 回入る）。
2. **今の emit_ui の初回失敗の大半は `"version": 1` の書き忘れ。** 初回で検証を通らなかった 78 件のうち 71 件。Shiki の修正ループで直るが、そのぶん往復と時間がかかる。Yui の採否に関係なく、Shiki 側で `version` を省略可能にすれば改善できる。
3. **簡易版の説明（B）は足りない。** 図が不要な質問にも図を出す（none-unneeded 30%）、構成図が弱い（stack 25%）。完全版（C、約 680 トークン）を既定にするのがよい。
4. **流れ図・構成図は emit_ui ではほぼ描けない**（flow 25%、stack 0%）。Yui では 70〜80%。残る失敗は、手順の粒度（「発見・報告」をまとめる、「納品」を飛ばす）と、構成図を流れ図で描いてしまうもの（stack を flow で出力）。
5. **Yui の記法と「短い JSON を本文中に」（D）の差は小さい。** グラフ系は同等、flow は D、stack と「図を出さない判断」は C が上。大きな差を生んでいるのは記法そのものより、「本文中に書く」「部品を絞った小さな説明」のほう。Yui の記法の利点は、Markdown として読める・途中から描ける・人が直せる点にある。
