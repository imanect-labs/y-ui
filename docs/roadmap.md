# Yui ロードマップ

今の位置は 0.7.0（未公開）。対応する図は 20 種類（bar / line / pie / scatter / stat / flow / stack / timeline / steps / tree / cards / progress / funnel / quadrant / gantt / compare / proscons / swot / checklist と、計算の calc）で、パーサ・SVG・React（ホバーとキーボード）・書き出し（PNG / SVG / クリップボード）がある。Shiki のチャットでは既定で有効（imanect-labs/shiki-platform#560）。

この文書の順番で進める。v0.6・v0.7・Shiki 側の組み込みは並行する。

## v0.7〜v0.8 — 図の種類を増やす

方針は今の 5 種類と同じ。

- モデルに書かせるのはデータだけ。見た目の指定は持たせない。
- モデルが書き慣れた形（表・箇条書き・`項目: 値`・番号付きリスト）を受ける。新しい記号は増やさない。
- 1 行ずつ確定して描ける。
- 種類を足すたびに、評価の課題を足し、今の種類の選び間違いが増えていないかを測る。

### v0.7（データの図）

| 種類 | 用途 | 記法の草案 |
|---|---|---|
| `pie` | 構成比・内訳（円グラフ） | `項目 \| 値` を並べる。`unit:` と `note:` は bar と同じ。値は 0 以上。**実装済み**（spec §5.5） |
| `scatter` | 2 つの量の関係（散布図） | 2 行目に `ラベル \| X の名前 \| Y の名前`、以降 `A社 \| 12 \| 30`。**実装済み**（§5.6） |
| `timeline` | 年表・沿革・予定 | `- 2024年4月: 出来事` または `時期 \| 出来事`。書いた順に並べる。**実装済み**（§5.7） |
| `steps` | 番号付きの手順・段取り | `1. 見出し: 説明`。分岐のある手順は flow。**実装済み**（§5.8） |
| `tree` | 階層（組織図・分類・目次） | 字下げした箇条書き（`- 親` → `  - 子`）。深さは 4 段まで。**実装済み**（§5.9） |

### v0.8（まとめ・比較の図）

| 種類 | 用途 | 記法の草案 |
|---|---|---|
| `cards` | 要点・特徴・選択肢の一覧 | `- 見出し: 本文`。**実装済み**（§5.10） |
| `gantt` | 工程表 | `タスク \| 開始 \| 終了`（日付か月）。**実装済み**（§5.14） |
| `funnel` | 段階ごとの減り方（営業・採用） | `段階 \| 数`。**実装済み**（§5.12） |
| `progress` | 目標に対する進捗 | `項目 \| 実績 \| 目標`。**実装済み**（§5.11） |
| `quadrant` | 2 軸の位置づけ（2×2） | `x: 低 → 高`・`y: 低 → 高` と `項目 \| x \| y`（0〜100）。**実装済み**（§5.13） |

### v0.9（比較・判断の図）

| 種類 | 用途 | 記法 |
|---|---|---|
| `compare` | 製品・プラン・案の項目ごとの比較（✓ / ✗ / △） | 見出し行と `項目 \| セル \| セル`、`推奨: 名前`。**実装済み**（§5.16） |
| `proscons` | 1 つの案の良い点と悪い点 | `メリット:` `デメリット:` の下に箇条書き。**実装済み**（§5.17） |
| `swot` | 強み・弱み・機会・脅威 | `強み:` などの見出しの下に箇条書き。**実装済み**（§5.18） |
| `checklist` | 確認事項・タスクの済・未 | `- [x]` `- [ ]` `- [~]`。**実装済み**（§5.19） |

評価（Luna、Shiki の説明）: 新しい 4 種類で 98.3%、全課題で 95.1%（16 種類の説明では 93.6%）。[eval-results-2026-10-15-v09.md](eval-results-2026-10-15-v09.md)。

あわせて、stack 以降の種類の見た目を整えた（文字と余白を大きく、線を控えめに、角を丸める）。cards は値（`見出し | ¥4,800 | 本文`）と ✓ の項目、steps・timeline は段落の説明を書ける。

候補（未着手）: `waterfall`（増減の内訳）、`radar`（複数の観点の点数）、`heatmap`（曜日 × 時間などの表の濃淡）、概念図（パネルの中の比率のブロックと矢印）。

`area`（面グラフ）は種類を増やさず、`line` の `stacked: true` として扱う（種類が増えるほど選び間違いが増えるため）。

### 種類を足す手順（1 種類ずつ）

1. 仕様（`docs/spec.md` §5）に記法・上限・診断を書く。
2. IR（`ir.ts`）・パーサ（`kinds/`）・テキスト化（`text.ts`・`export.ts` の HTML）。
3. 描画（`render/`）と React のホバー・キーボード（`targets`）。明暗・幅 390px で目で確かめる。
4. テスト（パーサ・描画・往復 `parseBlock(toSource(f))`）。
5. 評価の課題と採点（`eval/src/tasks`・`eval/src/score.ts`）。Luna で、新しい種類の合格率と、今の種類の合格率が下がっていないことを確かめる。
6. 説明文（`eval/prompts/miniui-full.md` と Shiki の `yui_guide.md`）。

## v0.9 — calc（画面内で完結する計算）

ローン・料金の試算・割り勘のように、利用者が値を動かすと結果が変わる図。入力（スライダー・数の増減・選択）と式と結果だけを持ち、式は Yui が解釈する（JavaScript を実行しない）。仕様: [docs/calc.md](calc.md)。**実装済み**（0.7.0）。評価の課題は 8 件（期待値つき）で、Shiki の説明で 95.8%。課題を 30 件に増やし、§7 の未決事項（表で比べる形・cards への式の埋め込み）を決める。
