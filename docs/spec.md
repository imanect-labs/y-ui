# Yui（結）記法仕様 v0.1（草案）

Yui は、Markdown の中に ` ```ui ` ブロックとして図を書くための小さな記法と、そのレンダラーです。
LLM（小さなモデルを含む）が少ない説明で正しく書けること、生成途中から描けること、どんな入力でも安全に表示できることを優先します。

名前の由来は「結（ゆい）」。文章と図、AI と人の書くものを 1 つの Markdown に結ぶ。リポジトリ名は `y-ui`、npm パッケージは `@imanect/yui`（`@imanect/yui/react` などのサブパスで分ける）。

参照実装: `packages/core`（パーサ・中間表現・テキスト化）。この文書と実装が食い違う場合は、この文書を正として実装を直します。

## 1. 設計原則

1. **LLM にはデータだけを書かせる。** 配置・配色・目盛り・余白はレンダラーが決める。部品の木構造は書かせない。
2. **モデルが書き慣れた形を受け付ける。** Markdown の表・箇条書き・Mermaid 風の矢印など、学習で見慣れた書き方をそのまま受ける。新しい記号は増やさない。
3. **1 行が処理の単位。** 改行で確定した行から順に描画できる。閉じフェンスを待たない。
4. **失敗は行単位で局所化し、黙って捨てない。** 不正な行は除外し、診断として利用者に見せる。値を推測で補ったり、別の値に置き換えたりしない。
5. **どんなテキストでも安全に描画できる。** HTML・URL・スクリプト・式を持たない。表示されるのは文字列と数値だけ。

## 2. ブロック

````
```ui
<種類> <タイトル>
<本文の行>…
```
````

- CommonMark のフェンスに従う（` ``` ` または `~~~` を 3 文字以上、行頭の空白 3 つまで、閉じは同じ文字で開き以上の長さ）。
- 情報文字列は `ui` または `yui`。`ui bar` / `ui:bar` のように種類を書いてもよい。その場合、1 行目はタイトルだけでよい。
- 他の言語のコードブロックの中にある ` ```ui ` は対象にしない。

## 3. 1 行目（ヘッダ）

`<種類> <タイトル>`。種類とタイトルの間は空白、`|`、`:`、`：` のどれでもよい（`bar | 売上`、`棒グラフ：売上`）。

| 種類 | 別名 | 内容 |
|---|---|---|
| `bar` | `column` `棒` `棒グラフ` | 棒グラフ |
| `line` | `折れ線` `折れ線グラフ` | 折れ線グラフ |
| `stat` | `kpi` `stats` | 数値カード |
| `flow` | `flowchart` `フロー` | 流れ図 |
| `stack` | `layers` `arch` `構成` `構成図` | 層構成図 |

- 種類が分からないブロックは図にしない（診断 `unknown_kind`）。レンダラーはソースをコードとして表示する。
- タイトル末尾の `[1]` `[1][2]` は引用番号として取り出す（ホストが出典表示に使う）。

## 4. 共通の書き方

### オプション行

`キー: 値` の形の行。種類ごとに使えるキーだけを解釈し、それ以外は本文として読む。

| キー（別名） | 種類 | 意味 |
|---|---|---|
| `note`（`注記` `注`） | すべて | 図の下の注記 |
| `src`（`source` `出典`） | すべて | データ参照。Yui 本体は解決せず、ホストが閲覧者の権限で解決する |
| `unit`（`単位`） | bar / line | 値の単位 |
| `stacked` | bar / line | 積み上げ（`true` / `はい`） |
| `horizontal` | bar | 横向きの棒 |
| `dir`（`direction` `方向` `向き`） | flow | `LR`（左→右）／ `TB`（上→下、既定） |

### 引用番号

行・セル・タイトルの末尾の `[n]` は引用番号として扱い、表示テキストからは外す。

### 箇条書き記号

行頭の `- ` `* ` `+ ` `・` `1. ` は取り除いて読む（stack では字下げの判定に使う）。

## 5. 種類ごとの書き方

### 5.1 bar / line

````
```ui
bar 売上推移 [1]
unit: 万円
月 | 売上 | 利益
1月 | 120 | 30
2月 | 150 | △10
```
````

- 最初の `|` 区切りの行が列名の行。1 列目はラベル列、2 列目以降が系列。
- 列名の行が無い（2 列目以降がすべて数値）場合は、列名を補う（`項目 | 値`、診断 `missing_header`）。
- `2024 | 2025年度` のように、2 列目以降がすべて年・月・期の表記なら、数値として読めても列名の行とみなす。
- 寛容に受ける形: GFM の表（前後の `|`、区切り行 `|---|`）、タブ区切り、1 系列の `1月: 120`。
- セルは §6 の数値として読む。空・`-`・`N/A`・`なし` は欠損（null）。数値として読めないセルがある行は、その行だけ除外する（診断 `bad_number`）。
- 列名より多いセルは無視する（診断 `extra_cells`）。少ない場合は欠損として補う。

### 5.2 stat

````
```ui
stat 今月の実績
売上 | 3,200万円 | 前年比 +18%
顧客数: 1,240社
```
````

- `項目 | 値 | 補足` または `項目: 値`。値は書かれた文字列のまま表示する（数値として読めれば比較用に保持）。

### 5.3 flow

````
```ui
flow 注文処理
注文 -> 在庫確認 -> 出荷
在庫確認 -なし-> 取り寄せ
```
````

- 矢印でつなぐ。連結（`A -> B -> C`）すると、隣り合うノードの間に辺を張る。
- 矢印: `->` `-->` `=>` `→` `⇒`。
- ラベル付き: `A -ラベル-> B`（前に空白が必要）、`A -->|ラベル| B`、`A -- ラベル --> B`。
- ノードは表示名がそのまま識別子。同じ名前は同じノード。
- Mermaid 風の定義も受ける: `A[注文]`（箱）、`B{在庫あり?}`（判断）、`C([完了])`（端点）。定義した id は、その後の行で同じノードを指す。`flowchart LR` / `graph TD` の行は向きとして読む。
- 矢印の無い行は、単独のノード。

### 5.4 stack

````
```ui
stack システム構成
- クライアント層: Web / Electron / 外部チャット
- Comma Product API: Task・Conversation・User・認証
↓ gRPC
- Salix — Agent Runtime: Elixir / Erlang OTP
  - Agent Process
  - Session / Journal
  - Scheduler / Loop
  - Lean Kernel
- LLM: OpenAI / Anthropic | Tools: 外部API / Device | Storage: DB / Object Store
note: 公開資料を基にした論理構成図。
```
````

- 1 段目の行が層。上から下へ積み、層の間に下向きの矢印を自動で引く。
- `名前: 説明`（`：` も可）で見出しと説明に分ける。`10:00` のように `:` の後に空白が無いものは分けない。
- 字下げした行は、直前の層の中の要素。3 段目以降の字下げは 2 段目として扱う（診断 `nested_too_deep`）。
- 1 行の中の `|` は横並び。字下げした行の中の `|` は、層の中の要素を増やす。
- `↓ ラベル`（`→` `->` も可）の行は、次の層の上の矢印に付くラベル。
- 箇条書き記号の無い行も層として読む。

## 6. 数値

| 書き方 | 値 |
|---|---|
| `1,200` `１，２００` | 1200（全角は NFKC で半角化） |
| `120万` `1.2億` `1億2,000万` | 1200000 / 120000000 / 120000000（`千` `万` `億` `兆`） |
| `△120` `▲120` `-120` `−120` | -120 |
| `+18%` | 18（単位 `%`） |
| `¥1,200` `$3.5` | 1200（単位 `円`） / 3.5（単位 `$`） |
| `320万円` `1,240人` | 3200000（単位 `円`） / 1240（単位 `人`） |
| `約120件` | 120（概数） |

- 後置の単位は 8 文字まで、数字を含まないこと。`120-150` のような範囲は数値ではない。
- 末尾の引用番号 `[n]` は数値の一部として読まない。

## 7. ストリーミング

- パーサは毎回ブロック全体を解析し直す（ブロックは小さいため。実測は eval の `truncation`）。
- 確定していない最後の行（改行で終わっていない行）は読まない。途中まで届いた `15` が `150` の一部である可能性があるため。
- 閉じフェンスが来ていないブロックも、確定した行までで描画する。ストリームが終わったら最後の行も確定させる。
- この規則により、生成途中で表示した行・項目・辺・層は、最終結果の先頭部分と一致し、表示量は減らない（`pnpm eval truncation` で全課題について検証）。

## 8. エラーと診断

- 診断は `{ line, severity: error | warning | info, code, message }`。message は日本語。
- error: 図にできない（`unknown_kind`、`empty`）。レンダラーはソースをコードとして表示する。
- warning: 一部を除外した（`bad_number`、`extra_cells`、`unrecognized_line`、`limit_exceeded`、`text_too_long`）。図に「n 行を表示できません」のように示す。
- info: 補った・解釈した（`missing_header`、`nested_too_deep`）。

## 9. 上限

| 対象 | 上限 |
|---|---|
| 1 つのテキスト（セル・ラベル・見出し） | 200 文字 |
| bar / line | 500 行 × 13 列 |
| stat | 24 項目 |
| flow | 60 ノード、100 辺 |
| stack | 12 層、横並び 8、層の中の要素 16 |

## 10. 中間表現・テキスト化

- 中間表現は `packages/core/src/ir.ts` の `Figure`。
- `toSource(figure)`: 正規形のソース。`parseBlock(toSource(f))` は `f` に戻る。
- `toText(figure)`: Yui 非対応の場所向けのテキスト（グラフは GFM の表、flow は「A → B」の箇条書き、stack は入れ子の箇条書き）。
- `transformMarkdown(md, "text")`: Markdown 中の ui ブロックをテキスト化する。解析できないブロックはソースのまま残す。

## 11. セキュリティ

- 段階 1（この仕様の範囲）には HTML・URL・スクリプト・式・イベントが無い。どんなテキストを入れても、表示されるのは文字列と数値だけ。
- `src` は不透明な文字列として保持するだけで、Yui 本体は取得しない。ホストが閲覧者の権限で解決する。

## 12. 描画（レンダラーの約束）

参照実装: `@imanect/yui/svg`（`renderSVG`）と `@imanect/yui/react`（`YuiFigure` / `YuiBlock`）。

- 配置・配色・目盛り・ラベルの間引きはレンダラーが決める。記法に見た目の指定は持たせない。
- 棒グラフは行が多い（15 行以上）か項目名が長いと横向きにする。流れ図は `dir: LR` でも幅に収まらなければ縦向きにする。流れ図の分岐（出る辺が 2 本以上）はひし形、ループは脇を回す。構成図の横並びは 1 つ 140px を下回るなら折り返す。
- 画面用（`theme: "auto"`）は CSS 変数で色を参照し、OS とページの明暗に追従する。書き出し用（`"light"` / `"dark"`）は色と寸法を焼き込む。どちらも同じレイアウトから作る。
- 各図の `<desc>` に、テキスト化（§10 の toText）した内容を入れる（読み上げ・色に頼らない確認のため）。
- 文字幅は既定で文字種ごとの表から見積もり、どの環境でも同じ配置にする（`measure` で差し替え可能）。
