# Yui（結）記法仕様 v0.1（草案）

Yui は、Markdown の中に ` ```ui ` ブロックとして図を書くための小さな記法と、そのレンダラーです。
LLM（小さなモデルを含む）が少ない説明で正しく書けること、生成途中から描けること、どんな入力でも安全に表示できることを優先します。

名前の由来は「結（ゆい）」。文章と図、AI と人の書くものを 1 つの Markdown に結ぶ。リポジトリ名は `y-ui`、npm パッケージは `@imanect/yui`（`@imanect/yui/react` などのサブパスで分ける）。

参照実装: `packages/core`（パーサ・中間表現・テキスト化）。この文書と実装が食い違う場合は、この文書を正として実装を直します。

## 1. 設計原則

1. **LLM にはデータだけを書かせる。** 配置・配色・目盛り・余白はレンダラーが決める。部品の木構造は書かせない。
2. **モデルが書き慣れた形を受け付ける。** Markdown の表・箇条書き・Mermaid 風の矢印など、学習で見慣れた書き方をそのまま受ける。新しい記号は増やさない。
3. **1 行が処理の単位。** 改行で確定した行から順に描画できる。閉じフェンスを待たない。
4. **失敗は行単位で局所化し、黙って捨てない。** 不正な行は除外し、診断として利用者に見せる。値を推測で補ったり、別の値に置き換えたりしない。
5. **どんなテキストでも安全に描画できる。** HTML・URL・スクリプト・式を持たない。表示されるのは文字列と数値だけ。

## 2. ブロック

````
```ui
<種類> <タイトル>
<本文の行>…
```
````

- CommonMark のフェンスに従う（` ``` ` または `~~~` を 3 文字以上、行頭の空白 3 つまで、閉じは同じ文字で開き以上の長さ）。
- 情報文字列は `ui` または `yui`。`ui bar` / `ui:bar` のように種類を書いてもよい。その場合、1 行目はタイトルだけでよい。
- 他の言語のコードブロックの中にある ` ```ui ` は対象にしない。

## 3. 1 行目（ヘッダ）

`<種類> <タイトル>`。種類とタイトルの間は空白、`|`、`:`、`：` のどれでもよい（`bar | 売上`、`棒グラフ：売上`）。

| 種類 | 別名 | 内容 |
|---|---|---|
| `bar` | `column` `棒` `棒グラフ` | 棒グラフ |
| `line` | `折れ線` `折れ線グラフ` | 折れ線グラフ |
| `pie` | `donut` `円` `円グラフ` `ドーナツ` | 円グラフ（構成比） |
| `stat` | `kpi` `stats` | 数値カード |
| `flow` | `flowchart` `フロー` | 流れ図 |
| `stack` | `layers` `arch` `構成` `構成図` | 層構成図 |
| `scatter` | `散布図` | 散布図 |
| `timeline` | `年表` `沿革` `タイムライン` | 年表 |
| `steps` | `step` `手順` `ステップ` | 分岐の無い手順 |
| `tree` | `ツリー` `階層` `組織図` | 階層（組織図・分類・目次） |
| `cards` | `card` `カード` `要点` | 要点のカード |
| `progress` | `進捗` `達成率` | 目標に対する進捗 |
| `funnel` | `ファネル` `歩留まり` | 段階ごとに減る数 |
| `quadrant` | `matrix` `4象限` `四象限` `マトリクス` | 2 軸の位置づけ（2×2） |
| `gantt` | `ガント` `ガントチャート` `工程表` | 工程表 |
| `calc` | `計算` `試算` `calculator` | 画面内で完結する計算（段階 2） |

- 種類が分からないブロックは図にしない（診断 `unknown_kind`）。レンダラーはソースをコードとして表示する。
- タイトル末尾の `[1]` `[1][2]` は引用番号として取り出す（ホストが出典表示に使う）。

## 4. 共通の書き方

### オプション行

`キー: 値` の形の行。種類ごとに使えるキーだけを解釈し、それ以外は本文として読む。

| キー（別名） | 種類 | 意味 |
|---|---|---|
| `note`（`注記` `注`） | すべて | 図の下の注記 |
| `src`（`source` `出典`） | すべて | データ参照。Yui 本体は解決せず、ホストが閲覧者の権限で解決する |
| `unit`（`単位`） | bar / line | 値の単位 |
| `stacked` | bar / line | 積み上げ（`true` / `はい`） |
| `horizontal` | bar | 横向きの棒 |
| `dir`（`direction` `方向` `向き`） | flow | `LR`（左→右）／ `TB`（上→下、既定） |

### 引用番号

行・セル・タイトルの末尾の `[n]` は引用番号として扱い、表示テキストからは外す。

### 箇条書き記号

行頭の `- ` `* ` `+ ` `・` `1. ` は取り除いて読む（stack では字下げの判定に使う）。

## 5. 種類ごとの書き方

全種類の一覧（用途・使い分け・例・上限）は [kinds.md](kinds.md)。

### 5.1 bar / line

````
```ui
bar 売上推移 [1]
unit: 万円
月 | 売上 | 利益
1月 | 120 | 30
2月 | 150 | △10
```
````

- 最初の `|` 区切りの行が列名の行。1 列目はラベル列、2 列目以降が系列。
- 列名の行が無い（2 列目以降がすべて数値）場合は、列名を補う（`項目 | 値`、診断 `missing_header`）。
- `2024 | 2025年度` のように、2 列目以降がすべて年・月・期の表記なら、数値として読めても列名の行とみなす。
- 寛容に受ける形: GFM の表（前後の `|`、区切り行 `|---|`）、タブ区切り、1 系列の `1月: 120`。
- セルは §6 の数値として読む。空・`-`・`N/A`・`なし` は欠損（null）。数値として読めないセルがある行は、その行だけ除外する（診断 `bad_number`）。
- 列名より多いセルは無視する（診断 `extra_cells`）。少ない場合は欠損として補う。

### 5.2 stat

````
```ui
stat 今月の実績
売上 | 3,200万円 | 前年比 +18%
顧客数: 1,240社
```
````

- `項目 | 値 | 補足` または `項目: 値`。値は書かれた文字列のまま表示する（数値として読めれば比較用に保持）。

### 5.3 flow

````
```ui
flow 注文処理
注文 -> 在庫確認 -> 出荷
在庫確認 -なし-> 取り寄せ
```
````

- 矢印でつなぐ。連結（`A -> B -> C`）すると、隣り合うノードの間に辺を張る。
- 矢印: `->` `-->` `=>` `→` `⇒`。
- ラベル付き: `A -ラベル-> B`（前に空白が必要）、`A -->|ラベル| B`、`A -- ラベル --> B`。
- ノードは表示名がそのまま識別子。同じ名前は同じノード。
- Mermaid 風の定義も受ける: `A[注文]`（箱）、`B{在庫あり?}`（判断）、`C([完了])`（端点）。定義した id は、その後の行で同じノードを指す。`flowchart LR` / `graph TD` の行は向きとして読む。丸括弧は id の直後だけを定義と読む（`Book (PDF/Text)` は名前のまま）。
- 矢印の無い行は、単独のノード。
- 枠（グループ）: `subgraph 名前` の行から `end` の行までを 1 つの枠で囲む。`subgraph S1[名前]` のように id も書ける。`## 名前` の行も枠の始まりとして読み、次の見出しまでを囲む。
  - ノードは、最初に書かれた枠に属する。枠の外で先に書いたノードも、後から枠の中に書けば入る。すでに別の枠に属するノードは移らないので、枠をまたぐ矢印は、枠の中・外のどちらに書いてもよい。
  - 枠の名前や id を矢印の端に書くと、枠そのものにつなぐ（`開始 -> S1`）。
  - 枠の中の `direction LR` / `direction TB` は、その枠の中の向き。書かなければ、枠の中は図の向きと直交する（横向きの図なら各枠の中は縦に並ぶ）。
  - 枠の中の枠は入れ子にせず、外に並べて描く（診断 `nested_too_deep`、info）。
  - `subgraph` `end` `direction` は小文字だけを予約語として読む（`End` という名前のノードを書けるように）。
- 強調: `**名前**`、Mermaid の `A:::クラス`・`style A …`・`class A クラス` の箱を強調して描く。色はレンダラーが決め、`classDef` `linkStyle` `click` と色の値は読まない（診断 `unrecognized_line`、info）。

### 5.4 stack

````
```ui
stack システム構成
- クライアント層: Web / Electron / 外部チャット
- Comma Product API: Task・Conversation・User・認証
↓ gRPC
- Salix — Agent Runtime: Elixir / Erlang OTP
  - Agent Process
  - Session / Journal
  - Scheduler / Loop
  - Lean Kernel
- LLM: OpenAI / Anthropic | Tools: 外部API / Device | Storage: DB / Object Store
note: 公開資料を基にした論理構成図。
```
````

- 1 段目の行が層。上から下へ積み、層の間に下向きの矢印を自動で引く。
- `名前: 説明`（`：` も可）で見出しと説明に分ける。`10:00` のように `:` の後に空白が無いものは分けない。
- 字下げした行は、直前の層の中の要素。3 段目以降の字下げは 2 段目として扱う（診断 `nested_too_deep`）。
- 1 行の中の `|` は横並び。字下げした行の中の `|` は、層の中の要素を増やす。
- `↓ ラベル`（`→` `->` も可）の行は、次の層の上の矢印に付くラベル。
- 箇条書き記号の無い行も層として読む。
- 層は書いた順に上から積む。利用側（画面）と基盤（データベース）のどちらを上に置くかは書き手が決める。

### 5.5 pie

````
```ui
pie 事業別の売上構成
unit: 億円
事業 | 売上
クラウド | 145
保守サポート | 98
研修 | 31
```
````

- 書き方は §5.1 と同じ（列名の行、GFM の表、`項目: 値`）。系列は 1 つだけ。3 列目以降は無視する（診断 `extra_cells`、info）。
- 値は 0 以上。欠損と負の値の行は除外する（診断 `bad_number`）。0 は扇を描かず凡例にだけ残す。
- 割合はレンダラーが計算する。モデルに割合を書かせない（合計が 100 にならない誤りを避けるため）。資料が割合しか持たない場合は、その数値を値として書く（合計が 100 前後なら割合はほぼそのまま）。
- 扇は書かれた順に並べ、並べ替えない（アンケートの「満足 → 不満」のような順序を壊さないため）。
- 項目は 12 まで（超えた分は除外、診断 `limit_exceeded`）。9 項目目以降は灰色で描く（診断 `limit_exceeded`、info）。項目が多いなら「その他」にまとめるか bar を使う。

### 5.6 scatter

````
```ui
scatter 店舗別の広告費と売上
店舗 | 広告費（万円） | 売上（百万円） | 地域
新宿 | 120 | 48 | 東京
梅田 | 95 | 39 | 大阪
```
````

- 最初の行が列名（ラベル列・横軸・縦軸、任意で 4 列目のまとまり）。2・3 列目が数値の行から始まる場合は列名を補う（`missing_header`）。単位は軸の名前に書く。
- X・Y のどちらかが数値として読めない・欠損の行は除外する（`bad_number`）。4 列目は、列名の行に 4 列目の名前があるときだけ色分けに使う。
- 点は 200 個まで。

### 5.7 timeline

````
```ui
timeline 沿革
- 2015年4月: 創業 [1]
- 2021年1月: 導入企業 100 社を突破
  クラウド版の提供を開始
10:00 開会
2023年 | 上場 | 東証グロース
```
````

- 1 行が 1 つの出来事。`時期: 出来事`、`時期 | 出来事 | 補足`、`時期 出来事`（先頭の語が数字を含む）、`10:00 出来事`（時刻は `:` で分けない）。
- 出来事が `見出し: 補足` なら補足に分ける。字下げした行は直前の出来事の補足に、段落として足す（1 行 1 段落。行頭の `- ` は落とす）。
- 時期は書かれた文字列のまま持ち、並べ替えない（新しい順に書けば新しい順に描く）。表の見出し行（`時期 | 出来事`）は読み飛ばす。
- 出来事は 40 まで。

### 5.8 steps

````
```ui
steps 経費精算の手順
1. 申請: 領収書を添えて入力する
2. 上長の承認
  金額が 10 万円を超える場合は部長の承認も要る
  - 差し戻されたら申請からやり直す
STEP3: 支払
```
````

- 1 行が 1 つの手順。`見出し: 説明`、`見出し | 説明`。番号（`1.` `1)` `STEP1:` `手順1`）と表の番号の列は落とし、書かれた順に振り直す（`Step 1〜3:` のような範囲は見出しとして残す）。字下げした行は直前の手順の説明に、段落として足す（1 行 1 段落。行頭の `- ` は落とす）。
- 分岐・合流・繰り返しは表せない。それらは flow で書く。
- 手順は 15 まで。

### 5.9 tree

````
```ui
tree 組織図
- 社長
  - 営業本部: 120名
    - 東日本営業部 | 西日本営業部
  - 開発本部
- 監査役
```
````

- 字下げの深さが階層。最上位は複数あってよい。`名前: 説明`。1 行の中の `|` は兄弟の並び。
- 深さは 4 段まで。5 段目以降は 4 段目に置く（`nested_too_deep`、info）。項目は 80 まで。

### 5.10 cards

````
```ui
cards 新プランの特徴
- 共有がかんたん: フォルダごとに権限を付けられる [1]
- 検索が速い
  社内文書を横断して答える
```
````

````
```ui
cards 料金プラン
- Starter | ¥4,800 | 月額相当
  - 基本分析
  - メールサポート
- Pro | ¥11,200 | 月額相当
  - 高度な分析
  - API アクセス
```
````

- `見出し: 本文`、`見出し | 本文`。字下げした行は本文の段落に足す。12 枚まで。
- `見出し | 値 | 本文`: 2 つ目のセルが数値（`¥4,800`・`98%`・`3 倍` のように数字を含む短い文字列）なら、見出しの下に大きく出す値にする。
- 字下げした `- 項目` は、本文の下に ✓ の付いた一覧として出す（プランの機能・含まれるもの）。1 枚に 8 項目まで。
- 1 つの数値だけを大きく見せるなら stat。

### 5.11 progress

````
```ui
progress 今期の目標の達成状況
項目 | 実績 | 目標
売上 | 8,200万円 | 1億円
新規 | 132 / 120
研修の受講率: 64%
```
````

- `項目 | 実績 | 目標`、`項目 | 実績 / 目標`、`項目: 64%`（% だけなら目標は 100%）。実績と目標は §6 の数値として読み、表示は書かれたまま。目標の無い行は除外する（`unrecognized_line`）。
- 達成率は実績 ÷ 目標。100% 以上は色を変える。値が小さいほど良い指標（解約率など）は表せない（棒グラフか stat で書く）。20 項目まで。

### 5.12 funnel

````
```ui
funnel 採用の選考状況
unit: 人
応募 | 1200
書類選考通過 | 420
内定承諾 | 30
```
````

- `段階 | 数`、`段階: 数`。最初の段階から順に書く。数は 0 以上（負の数の行は除外）。単位は `unit:` か、最初に単位付きで書かれた数から取る。
- 前の段階からの割合と、最初の段階からの割合はレンダラーが計算する。10 段階まで。

### 5.13 quadrant

````
```ui
quadrant 施策の優先度
x: 効果
y: 実現しやすさ
右上: すぐやる
左下: 見送り
フォームの改善 | 70 | 85 [1]
多言語対応 | 60 | 20
```
````

- `x:`・`y:`（`横軸:`・`縦軸:` も可）が軸の名前。最初の行が `名前 | 効果 | 工数` のような見出しなら、軸の名前として使う。
- `右上:`・`左上:`・`左下:`・`右下:`（`第1象限:` 〜 `第4象限:` も可）が象限の名前（任意）。右上を淡く塗る。
- 項目は `名前 | 横 | 縦`。位置は 0〜100。範囲外は丸める（`bad_number`）。30 項目まで。

### 5.14 gantt

````
```ui
gantt 導入の工程
タスク | 開始 | 終了
要件定義 | 2025/4/1 | 2025/4/30
設計: 5/1 〜 6/15
本番稼働 | 10/1
```
````

- `タスク | 開始 | 終了`、`タスク: 開始 〜 終了`、`タスク | 開始〜終了`。終了が無く 1 日だけならマイルストーン（ひし形）。
- 日付は `2025-04-01`・`2025/4/1`・`2025年4月1日`・`4/1`・`4月1日`・`2025年4月`・`4月`。月だけなら開始はその月の 1 日、終了は末日。年の無い日付は、直前に書かれた年を引き継ぐ。終了の月日が開始より前なら翌年とみなす。
- 終了が開始より前・日付として読めない行は除外する（`bad_number`）。30 タスクまで。
- 目盛りは、期間が 2 か月を超えれば月ごと、それ以下は 7 日ごと。

### 5.16 compare

````
```ui
compare プランの比較
推奨: Pro
機能 | Starter | Pro | Business
料金 | ¥980 | ¥2,240 | ¥4,400
SSO | ✗ | ✓ | ✓
監査ログ | なし | △ 90 日 | ✓ 無期限
```
````

- 最初の表の行が見出し（`項目 | 選択肢 | …`）。比べる選択肢は 6 つ、項目は 30 まで。
- セルの先頭の印を読む。`✓` `✔` `○` `◎` `あり` `対応` `可` `yes` は ✓、`✗` `×` `-` `なし` `非対応` `不可` `no` は ✗、`△` `一部` `限定` `オプション` は △。印の後ろの文字はそのまま添える（`△ 90 日`）。印の語が別の語の一部なら（`可能`）印にしない。
- `推奨: 選択肢`（`おすすめ:` `Recommended:` も可）: その列を淡く塗り、見出しの上に札を付ける。見出しに無い名前なら診断を出して無視する。
- 数値の大小を比べるなら bar、選択肢の要点を並べるだけなら cards。

### 5.17 proscons

````
```ui
proscons 週休 3 日制の導入
メリット:
- 定着率が上がる: 試行したチームで退職が減った
- 集中して働ける
デメリット:
- 顧客対応が手薄になる
```
````

- `メリット` `利点` `良い点` `長所` `Pros` の見出しと、`デメリット` `欠点` `悪い点` `短所` `リスク` `課題` `Cons` の見出し（`:` 付き、`## ` 付きも可）の下に箇条書き。見出しは書かれたまま表示する。

## 6. 数値

| 書き方 | 値 |
|---|---|
| `1,200` `１，２００` | 1200（全角は NFKC で半角化） |
| `120万` `1.2億` `1億2,000万` | 1200000 / 120000000 / 120000000（`千` `万` `億` `兆`） |
| `△120` `▲120` `-120` `−120` | -120 |
| `+18%` | 18（単位 `%`） |
| `¥1,200` `$3.5` | 1200（単位 `円`） / 3.5（単位 `$`） |
| `320万円` `1,240人` | 3200000（単位 `円`） / 1240（単位 `人`） |
| `約120件` | 120（概数） |

- 後置の単位は 8 文字まで、数字を含まないこと。`120-150` のような範囲は数値ではない。
- 末尾の引用番号 `[n]` は数値の一部として読まない。

## 7. ストリーミング

- パーサは毎回ブロック全体を解析し直す（ブロックは小さいため。実測は eval の `truncation`）。
- 確定していない最後の行（改行で終わっていない行）は読まない。途中まで届いた `15` が `150` の一部である可能性があるため。
- 閉じフェンスが来ていないブロックも、確定した行までで描画する。ストリームが終わったら最後の行も確定させる。
- この規則により、生成途中で表示した行・項目・辺・層は、最終結果の先頭部分と一致し、表示量は減らない（`pnpm eval truncation` で全課題について検証）。

## 8. エラーと診断

- 診断は `{ line, severity: error | warning | info, code, message }`。message は日本語。
- error: 図にできない（`unknown_kind`、`empty`）。レンダラーはソースをコードとして表示する。
- warning: 一部を除外した（`bad_number`、`extra_cells`、`unrecognized_line`、`limit_exceeded`、`text_too_long`）。図に「n 行を表示できません」のように示す。
- info: 補った・解釈した（`missing_header`、`nested_too_deep`）。

## 10. 中間表現・テキスト化

- 中間表現は `packages/core/src/ir.ts` の `Figure`。
- `toSource(figure)`: 正規形のソース。`parseBlock(toSource(f))` は `f` に戻る。
- `toText(figure)`: Yui 非対応の場所向けのテキスト（グラフ・散布図は GFM の表（円グラフは割合の列を足す）、年表・階層は箇条書き、手順は番号付きの箇条書き、flow は「A → B」の箇条書き、stack は入れ子の箇条書き）。
- `transformMarkdown(md, "text")`: Markdown 中の ui ブロックをテキスト化する。解析できないブロックはソースのまま残す。

## 11. セキュリティ

- 段階 1（この仕様の範囲）には HTML・URL・スクリプト・式・イベントが無い。どんなテキストを入れても、表示されるのは文字列と数値だけ。
- `src` は不透明な文字列として保持するだけで、Yui 本体は取得しない。ホストが閲覧者の権限で解決する。

## 12. 描画（レンダラーの約束）

参照実装: `@imanect/yui/svg`（`renderSVG`）と `@imanect/yui/react`（`YuiFigure` / `YuiBlock`）。

- 配置・配色・目盛り・ラベルの間引きはレンダラーが決める。記法に見た目の指定は持たせない。
- 棒グラフは行が多い（15 行以上）か項目名が長いと横向きにする（6 本以下の棒は、縦のままだと横軸の項目名を間引くことになるなら横向きにする。7 本以上は項目名が区画の 1.6 倍を超えるまで 1 つおきに間引いて縦のまま）。流れ図は `dir: LR` でも幅に収まらなければ縦向きにする。流れ図の分岐（出る辺が 2 本以上）はひし形、ループは脇を回す。枠のある流れ図では、枠をまたぐ辺は分岐に数えない（段階から次の段階への受け渡しのため）。枠のある流れ図は、枠の中を組んでから枠を段に並べ、枠をまたぐ辺は段の間の通路を通す（行き先が同じ辺は 1 本にまとめる）。枠は系列色を順に使った破線で囲み、中の箱の枠線もその色にする。横向きで幅に収まらなければ枠を縦に積み、それでも収まらなければ枠の中も縦にする。箱から段の向きにまっすぐ出られない辺は、横から出して枠の外側を回す。構成図の横並びは 1 つ 140px を下回るなら折り返す。円グラフはドーナツにして中央に合計を置き、値と割合は扇に載せず凡例に並べる（幅 460px 未満なら凡例は下）。割合は 10% 未満で小数 1 桁、それ以上は整数。値がすべて整数の軸（人数・回数など）は、目盛りも整数だけにする（1 未満の間隔や 2.5 刻みを使わない）。目盛りの数字は、隣どうしが同じ表記にならない桁数まで出す。散布図の軸は、0 を含めると点が片寄る場合は 0 から始めない。点が 15 個までなら点の横に名前を添え、重なる名前は省く。年表と手順は、項目が少なく見出しが列の幅に収まれば横に並べ、そうでなければ縦に並べる。階層は、末端まで横に並べて収まれば組織図、末端を親の下に縦に積めば収まれば積んだ組織図、どちらも収まらなければ字下げの一覧にする。比較表は、印の横に 3 文字も入らない狭い列（狭い幅で列が多い）では印だけを描き、セルの文字はツールチップで出す。
- 画面用（`theme: "auto"`）は CSS 変数で色を参照し、明暗はページの明示（`<html class="dark">`・`data-theme`）を優先し、無ければ OS の設定に追従する。書き出し用（`"light"` / `"dark"`）は色と寸法を焼き込む。どちらも同じレイアウトから作る。
- 各図の `<desc>` に、テキスト化（§10 の toText）した内容を入れる（読み上げ・色に頼らない確認のため）。
- 画面用（React）はホバー・タップ・キーボードで値を出す。円グラフは扇と凡例の行のどちらでもその項目の値と割合を出し、他の扇を薄くする。散布図は点ごとに名前と X・Y を出す。年表・手順は項目ごとに全文（省略した文字を含む）を出す。階層は載せた項目とその祖先だけを残す。棒・折れ線は横軸の 1 区画（横向きの棒は 1 行）ごとに全系列の値と単位をツールチップに出し、棒はその区画以外を薄くし、折れ線は縦線と点で示す。流れ図は載せた箱と、つながる線・前後の箱だけを残して薄くする。図は 1 つのタブ位置で、矢印キーで順に動かし、Esc で閉じ、値は読み上げ領域にも出す。出現時のアニメーションは付けず、強調の切り替え（約 0.12 秒）も OS の「視差効果を減らす」設定では止める。書き出し用の SVG には出さない。
- 文字幅は既定で文字種ごとの表から見積もり、どの環境でも同じ配置にする（`measure` で差し替え可能）。
